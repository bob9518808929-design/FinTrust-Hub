📋 系统总结说明

项目定位

AI 驱动的金融信任枢纽系统（FinTrust Hub）——财务顾问公司的整合平台 + AI 信任枢纽。

不替代银行核心 / 担保业务 / 保险核心 / 评估 / 法律 / 审计等具体业务系统，而是作为信任中介连接企业、银行、担保、保险四方。

核心价值：让中小企业融资从"盲盒"变成"白盒"——通过 AI 评估 + 渐进解锁机制，降低信息不对称，培育金融机构对小企业的信任。

技术栈

FastAPI Vue 3 + TS PostgreSQL Redis Temporal EMQX/MQTT Loki + Promtail K8s/Helm Docker Compose psutil

核心设计哲学

  • 结构驱动：配置优于训练，结构第一性
  • 白盒可逆：所有决策可追溯、可解释、可回滚
  • 知识从 LLM 蒸馏：将 LLM 能力固化为规则与结构化数据
  • 渐进调节：取类比象，P2 暂定性，P21 控制节律，P25 元变量演化
  • API 接入优先：A 档 API 接入 + B 档自研护城河 + C 档独立兜底备选
  • 机构接入是增量而非前提：零机构接入时系统仍能为企业提供独立价值
  • 傻瓜式操作：不让用户做选择题，只让用户做判断题或填空题
  • 互联网免费 / 对赌思维：打穿传统行业壁垒

业务架构（四层）

  • 企业层：注册 → 数字化改造 → 融资入口解锁 → 持续培育
  • 银行层：信任培育期 4 阶段渐进解锁（L4 只读 → L3 咨询 → L2 小额自动 → L1 全自动）
  • 担保/保险层：押品评估、核保核赔、风险共担
  • 监管层：沙盒穿透报告、监管账户、授信乘数、冻结/解冻

关键硬约束（摘选）

  • CRITICAL 所有中间件必须使用 async/await，禁用回调风格
  • CRITICAL AI 决策弹窗队列上限为 3，超限降级为非阻塞 toast
  • CRITICAL 不可逆决策（审批/风控）必须阻塞模态窗二次确认
  • CRITICAL 所有 AI 通知 toast 需含 × 关闭 + 操作按钮，z-index=9500
  • CRITICAL 合作模式（企业/银行/担保/保险）必须支持多选 pill 按钮组
  • CRITICAL 边缘案例触发后必须在所有 Tab 顶部显示全局告警横幅
  • CRITICAL 改造完成后必须回写 hasReformed / financingUnlocked
  • 系统字体栈优先（避免 Google Fonts CDN 在国内 3.3s 首屏阻塞）
  • 所有资源 URL 需加版本参数（?v=22）强制刷新缓存
