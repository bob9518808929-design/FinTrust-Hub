## 一、核心设计原则（五条铁律）

0. **改造优先（v5.0 新增）**: 所有融资撮合必须以"企业已完成合规化改造"为前置条件。企业改造不是可选服务，而是系统的核心业务起点。AI 驱动的改造引擎是整个 FinTrust Hub 的第一层能力。

1. **叙事流优先**: 8 个视图（Tab0-Tab7）按业务故事顺序排列。用户从"企业数据体检与改造"开始，逐步看到"AI 如何改造 → 如何撮合融资 → 银行如何监控 → 机构如何协作 → AI 全局观察"。

2. **因果链可见**: 所有参数联动必须通过"联动日志面板"实时输出因果链，过程比结果更重要。日志支持过滤和导出。

3. **AI 作为操作者**: AI 驾驶舱放在最后作为"上帝视角"，而非第一个 Tab。叙事流是"先看业务发生，再看 AI 在幕后做了什么"。**改造引擎也遵循此原则——用户先在 Tab0 看到改造方案和进度，再在 Tab7 看到 AI 的幕后决策**。

4. **全角色覆盖**: 8 个视图覆盖系统所有核心角色——企业、财务顾问、银行、担保公司、保险公司、AI 观察者，无一遗漏。

5. **合法边界（v5.0 强化）**: AI 生成的所有改造方案必须通过 R7 法律合规引擎的红线检测。绝对禁止虚开发票、伪造流水、隐匿收入等违法行为。合法边界分为"绝对红线（AI 必须拒绝）""灰色地带（需法律审核）""绿色合规区（AI 可自主执行）"三级。

## 一补、三档分类能力地图（spec v2.0 对齐 + v5.0 改造引擎补充）

> **目的**: 模拟器必须能清晰演示 FinTrust Hub 生产系统对每项能力的"三档分类决策"——哪些走 API 接入、哪些必须自研、哪些作为独立兜底。v5.0 在此基础上新增"改造引擎 R1-R10 作为系统最核心的自研模块"。

## 二、最终视图结构（Tab0-Tab7 + Tab8 兜底引擎 + 联动日志面板）

### 叙事流（v5.0 重构）

```
[Tab0 企业改造工作台] ← v5.0 新增，叙事流起点
  企业数据体检 → 8 维差距诊断 → AI 生成改造方案(3级激进程度)
  → AI 编排任务流(DAG) → AI 执行任务(L2-L4) → 改造进度追踪
  → 合规审核 → 改造完成 → 推送至 Tab1
     ↓
[Tab1 企业端工作台]  已完成改造的企业发起融资需求、配置数据流/模块/自主度/字段可见范围
     ↓
[Tab2 流程模拟器]  AI路由(L1-L4)、五流验证、政策校验、银行竞标比价、票据再贴现
     ↓                        ↓ (L3/L4)
[Tab3 审批台]  ← 人类决策      [联动日志面板] (贯穿所有Tab的底部面板)
     ↓
[Tab4 银行端]  信用画像、贷后监管、预警、脱敏对比
     ↓
[Tab5 担保与保险协作台]  担保申请/保前审查/反担保、投保/核保/保单/理赔
     ↓
[Tab6 财务顾问运营台]  全局仪表盘、撮合工作台、佣金结算
     ↓
[Tab7 AI驾驶舱]  全局观察AI操作全景、决策回溯(含置信度+改造推理链)、自主度监控
     ↓
[Tab8 独立兜底引擎控制台]  15 外部 API + B1-B12 + R1-R10 + C1-C7 + 兜底降级链 + 独立运行模式 + 投入仪表盘
```

> **Tab0 在叙事流最前的原因**: 这是 v5.0 的核心定位升级——系统不仅是融资撮合平台，更是企业改造平台。企业必须先通过改造引擎的合规化改造，才能进入融资撮合流程。Tab0 回答"企业数据怎么才能被银行接受"这个核心问题。

### 二补.5 合法边界三级定义（R7 合规引擎输入）

#### 绝对红线（AI 必须拒绝生成）
- 虚开发票（包括为融资而虚开）
- 伪造银行流水 / 物流单据 / 合同
- 隐匿收入偷逃税款（金额占应纳税额 10% 以上）
- 提供虚假财务报表骗取贷款
- 利用空壳公司虚构贸易背景
- 非法买卖资质牌照

#### 灰色地带（需法律审核）
- 反向收购壳公司 → 必须真实经营延续
- 股权代持 → 必须如实披露
- 关联交易合并报表 → 必须符合企业会计准则
- 税收优惠追溯申请 → 必须真实符合优惠条件
- 法人变更 → 不能用于逃避债务

#### 绿色合规区（AI 可自主执行）
- 补缴税款 + 滞纳金
- 纳税信用修复申请
- 资产盘活（保理/租赁/质押）
- 政策红利对接（政府担保/资质认定/贴息）
- 业务真实性补全（合同/物流/社保）
- 债务整合优化

## 七、供应链金融子系统 (SCF v6.0 新增)

> **版本**: v6.0 新增子系统（在 v5.0 基础上新增 **Tab11 供应链金融工作台 + SC1-SC10 引擎族 + 13 维供应链画像 + 关系图谱 + 企业黑白名单 + SCF 产品价格库 + 独立业务闭环**）
> **日期**: 2026-08-18
> **状态**: 已确认，可启动开发
> **设计依据**: 用户多轮讨论 — SCF 必须作为独立业务闭环构建，包含企业入口、数据库、画像、关系图谱四大要素，覆盖黑白名单/信用/产品/价格/市场完整体系

### 七.1 设计目标与边界

**核心定位**: 将 FinTrust Hub 从"单一企业融资撮合平台"升级为"供应链金融信任枢纽"，服务范围从中小企业扩展至整条产业链。SCF 子系统作为平行于 Tab0 改造引擎的独立闭环，与 Tab0 相互引用但各自独立。

**独立闭环起点→终点**:
```
起点: 核心企业认证 (Anchor Certification)
  ↓ SC1 供应链画像 (构建关系网络)
  ↓ SC2 黑白名单筛选 (准入过滤)
  ↓ SC3 信用传导计算 (生成传导信用分)
  ↓ SC4 贸易真实性验证 (五流+贸易专项)
  ↓ SC5 产品智能路由 (匹配 SCF 产品)
  ↓ SC6 动态定价 (利率+费率计算)
  ↓ SC7 风险扩散评估 (供应链风险预警)
  ↓ SC8 机构撮合 (银行/保理公司竞标)
  ↓ SC9 履约监控 (贷后贸易持续验证)
终点: 案例入库 (SC10 学习) + 信用回流到 SC2/SC3 (形成闭环)
```

**与 Tab0 改造引擎的边界**:
- Tab0 改造引擎 (R1-R10): 管单个企业自身合规化改造 (D级→A级)
- Tab11 SCF 引擎 (SC1-SC10): 管供应链网络中的贸易融资撮合
- 协同关系: Tab0 改造完成 → 企业可作为 SCF 的"合格核心企业"; SCF 信用传导 → 可反向影响企业改造的信用维度评分
- 两者相互引用但各自独立闭环

### 七.2 四大要素设计

#### 要素一: 供应链企业入口 (3 种角色入驻)

| 入口类型 | 角色 | 准入条件 | 数据要求 |
|---------|------|---------|---------|
| 核心企业入口 | Anchor | 信用分≥750 + 改造等级≥B+ | 全量8维画像 + 上下游清单 |
| 供应商入口 | Supplier | 核心企业推荐 or 独立入驻 | 基础画像 + 供货历史 |
| 经销商入口 | Distributor | 核心企业推荐 or 独立入驻 | 基础画像 + 销售历史 |

**入驻流程**: 申请 → 角色认证 → 数据授权 → 黑白名单校验 → 画像构建 → 关系建立 → 入网

**关键决策**: SCF 企业入口独立于顶部导航的企业选择器，新入驻企业加入 `State.scfDatabase.enterprises` 独立数组，不污染现有 `State.enterprises`。现有 E001-E004 作为核心企业候选。

#### 要素二: 供应链企业数据库 (4 层架构)

```
Layer 1: 主数据库 (Master Data)
  ├── SCF 企业主数据 (SCF_ENTERPRISES)
  ├── SCF 产品数据库 (SCF_PRODUCTS)
  └── SCF 机构数据库 (SCF_INSTITUTIONS)

Layer 2: 关系数据库 (Relationship Data)
  ├── 供应链关系 (SCF_RELATIONSHIPS)
  ├── 贸易记录 (SCF_TRADES)
  └── 黑白名单 (SCF_BLACKLIST / SCF_WHITELIST)

Layer 3: 交易数据库 (Transaction Data)
  ├── 融资申请 (SCF_FINANCING_REQUESTS)
  ├── 放款记录 (SCF_LOANS)
  └── 还款记录 (SCF_REPAYMENTS)

Layer 4: 风控数据库 (Risk Data)
  ├── 风险事件 (SCF_RISK_EVENTS)
  ├── 信用传导记录 (SCF_CREDIT_PROPAGATION)
  └── 履约记录 (SCF_PERFORMANCE)
```

**存储策略**: 内存为主 (`State.scfDatabase`) + localStorage 快照 (`fintrust_scf_db_v1`)，提供"重置数据库"按钮恢复初始 Mock 数据。

#### 要素三: 供应链企业画像 (13 维体系)

```
【供应链 5 维】(SCF 新增)
├── 交易稳定性 (tradeStability)       📈 交易频次/金额波动率
├── 贸易真实性 (tradeAuthenticity)    ✅ 五流验证通过率
├── 合作忠诚度 (cooperationLoyalty)   🤝 合作年限/集中度
├── 履约可靠度 (performanceReliability) ⏰ 按时交货/还款率
└── 网络位置分 (networkPosition)      🕸 在图谱中的中心度
```

**三层信用体系**:
- 独立信用 (企业自身信用分)
- 传导信用 (核心企业信用传导): `传导分 = 基础分×0.5 + 核心企业分×0.3×合作稳定系数 + 历史交易加成×0.2`
- 场景信用 (特定贸易背景下): `场景分 = 传导分×贸易验证通过率 + 押品覆盖率×0.2`

#### 要素四: 供应链关系图谱

**数据结构**: 有向图模型，节点=企业，边=供应链关系
- 节点属性: id, name, type(anchor/supplier/distributor), creditScore, profileScore, seatLevel, status
- 边属性: source, target, type(supply/purchase/distribute), weight(关系强度), tradeVolume, direction

**可视化**: 复用系统已引入的 ECharts `graph` 力导向图
- 核心企业节点最大 (60px)，橙色
- 供应商节点蓝色，经销商节点绿色
- 边宽度按关系强度渲染

**图算法分析能力**:
| 分析能力 | 算法 | 业务应用 |
|---------|------|---------|
| 中心度分析 | Degree/Betweenness Centrality | 识别关键节点企业 |
| 社区发现 | Louvain 算法 | 识别供应链子网络 |
| 路径分析 | 最短路径 | 风险传导路径追踪 |
| 环检测 | DFS 环检测 | 关联方循环交易识别 (复用 B7) |
| 连通性分析 | 连通分量 | 供应链完整性评估 |

### 七.4 SCF 产品库与价格库

**5 类 SCF 金融产品**:

| 产品 | 类型 | 适用角色 | 融资比例 | 基础费率 | 前置条件 |
|-----|------|---------|---------|---------|---------|
| 保理融资 | 应收类 | 供应商 | 80% | LPR+1.5% + 0.5%-2% | 发票+合同+签收+核心企业确权 |
| 反保理 | 应付类 | 核心企业发起 | 90% | LPR+1.0% | 采购订单+发票+付款承诺 |
| 预付款融资 | 预付类 | 经销商 | 50% | LPR+2.0% | 合同+供应协议 |
| 存货融资 | 存货类 | 供应商/经销商 | 60% | LPR+2.5% | 存货盘点+IoT 监控+保险 |
| 订单融资 | 订单类 | 供应商 | 70% | LPR+1.8% | 采购订单+核心企业信用传导 |

**定价联动机制** (复用现有 `simulateBankBids`):
- 核心企业信用分 → 基础利率折扣 (-0.3% / +0.5%)
- 贸易验证通过率 → 风险溢价 (verified: -0.2%, partial: +0.3%, unverified: 拒绝)
- 黑白名单状态 → 准入门槛 (blacklist: 拒绝, warning: +1.0%)
- 季节性窗口 → 利率波动 (复用 `SEASONAL_WINDOWS`)
